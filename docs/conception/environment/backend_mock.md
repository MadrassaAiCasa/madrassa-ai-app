# Backend Mock (MSW)

## Short Description

MSW (Mock Service Worker) intercepts API calls at the network layer, enabling frontend development and testing before the backend exists.

## How It Works

- **Browser** — service worker intercepts `fetch`, `axios`, `XMLHttpRequest` calls; works in dev
- **Node.js** — `msw/node` server intercepts HTTP calls in tests
- Same handler definitions work in both environments

## File Structure

```
src/mocks/
├── index.ts              → common, re-exports setup
├── server.ts             → common, test server (msw/node)
├── setUp.ts              → common, browser worker setup
├── browser.ts            → common, setupWorker for browser
└── handlers/
    ├── index.ts          → common, merges all feature handlers
    └── auth/             → auth feature mock
        ├── index.ts       → merges all auth handlers
        ├── mockStore.ts   → in-memory store + types
        ├── login.ts
        ├── session.ts
        ├── refresh.ts
        └── logout.ts
```

**Common files** — exist once, set up MSW for browser and tests.

**Per-feature files** — `handlers/<feature>/` holds all endpoints for that feature. Each feature gets its own `mockStore.ts` to cover all use cases so the frontend can be tested completely without a real backend.

## Mock Store

Each feature has its own `mockStore.ts` — `src/mocks/handlers/<feature>/mockStore.ts`. For auth: `src/mocks/handlers/auth/mockStore.ts`.

The store is an in-memory object modeling the server's state for that feature. Handlers read/write to it. Tests reset the store in `src/test/setupMSW.ts` to ensure each test starts clean.

## Endpoints

Each feature folder has one file per endpoint. Here is an example for auth:

| Method | Path            | File         | What it does                                                                                |
| ------ | --------------- | ------------ | ------------------------------------------------------------------------------------------- |
| POST   | `/auth/login`   | `login.ts`   | Validates credentials, sets `isAuthenticated = true`, returns access token + refresh cookie |
| GET    | `/auth/session` | `session.ts` | Returns logged-in user if valid refresh token exists                                        |
| POST   | `/auth/refresh` | `refresh.ts` | Issues new access token, rotates refresh cookie                                             |
| POST   | `/auth/logout`  | `logout.ts`  | Clears session state                                                                        |

## Development Usage

`src/mocks/setUp.ts` checks `VITE_USE_MOCKS` env var and starts the service worker:

```ts
// src/mocks/setUp.ts
async function enableMocking() {
    if (import.meta.env.VITE_USE_MOCKS !== 'true') return;
    await worker.start({ onUnhandledRequest: 'bypass' });
}
```

Call it once in `main.tsx` before rendering:

```ts
// main.tsx
import enableMocking from './mocks/setUp';

async function main() {
    await enableMocking();
    // render app
}

main();
```

## Test Usage

Tests use the Node server (`msw/node`) — no browser service worker. Import `server` from `mocks/server.ts` and `mockStore` to reset state between tests. No env var needed — mocks are always active in tests.

```ts
// src/test/setupMSW.ts
import { beforeAll, afterAll, afterEach } from 'vitest';
import { server } from '../mocks/server';
import { mockStore } from '../mocks/handlers/auth/mockStore';

beforeAll(() => server.listen());

afterEach(() => {
    server.resetHandlers();
    mockStore.isAuthenticated = false; // reset store state
});

afterAll(() => server.close());
```

Reference in `vitest.config.ts` via `setupFiles`.

## Adding New Handlers

When a new feature needs mocking:

1. Create `src/mocks/handlers/<feature>/` folder
2. Add `index.ts` merging all handlers from that feature
3. Add feature handlers to `src/mocks/handlers/index.ts`
4. Add to `src/mocks/server.ts` and `src/mocks/browser.ts`

## Notes

- `public/mockServiceWorker.js` generated by `npx msw init public/`
- `server.resetHandlers()` between tests prevents handler pollution
- `VITE_USE_MOCKS=true` toggles mocks in dev; tests always use mocks
